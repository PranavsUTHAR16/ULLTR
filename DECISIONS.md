| **DEC-001** | Architecture | Complex mathematical divergence between backtest and forward test engines. | Extract pure calculation cores into `forward_tester/core/model_07_core.py` and `forward_tester/core/strategy_6_core.py`. | Eliminates copy-paste drift. | **DEC-003** | Parity | `main07.py` line 240 and line 311 double-counted rolls on entry and rollover matches. | Remove duplicate `day_rolls_count += 1` on line 240. | Rollover matches are zero-turnover events that incur zero exchange friction. | **DEC-004** | Data Sourcing | `load_session_from_csv()` loaded `session_bars_<date>.csv` containing NIFTY FUTURES order-flow data instead of SPOT bars. | Reject CSV files containing futures indicators (`delta`, `oi`, `cum_cvd`) and require spot data from ClickHouse `nifty` table. | Futures trade at variable basis/premium (+20 to +100 pts) relative to spot, corrupting ATM strike selection and moneyness. | ADOPTED |
| **DEC-005** | Telemetry | Live engine had no raw incoming message log, preventing byte-level historical replay of live sessions. | Implement append-only Parquet storage in `forward_tester/raw_logger.py` capturing `message_id`, `receive_time_utc`, `redis_key`, `event_type`, `payload_json`. | High throughput, columnar compression, non-blocking buffering, guarantees exact historical replayability. | ADOPTED |
| **DEC-006** | Dead Code Removal | 4 retired models (`model_0216.py`, `dynamic_dte.py`, `ultra_tsmom.py`, `cas_model.py`) remained in engine. | Created backup tag `backup-pre-model-cleanup` and removed 2,849 lines of dead code and obsolete test suites. | Model 06 and Model 07 do not depend on retired models. Streamlined engine reduced memory footprint and eliminated collection errors. | ADOPTED |
| **DEC-007** | Mathematical Parity | `main07.py` line 264 calculated opposite CE harvest as `0.30 * p_pe_0` instead of `0.30 * p_ce_0`. | Corrected typo to `p_ce_exit = max(0.20, p_ce_0 * 0.30)`. | Resolves ₹222.30 discrepancy on 2026-09-24, achieving exact 100.000% parity (+₹282.10) with the forward replay engine. | ADOPTED |
| **DEC-008** | Instrument Selection | `strategy_6.py:_select_closer_expiry()` capped DTE at 5 days (`0 <= dte <= 5`), failing Wednesday sessions (DTE=6). | Remove DTE <= 5 ceiling (`dte >= 0`) and allow simulated `as_of_date` passing to `get_front_expiry()`. | Backtest logic (`vol_adaptive_backtest.py:366-367`) checks `dte_n <= dte_s` with no upper bound. | **DEC-009** | Infrastructure | Old ClickHouse Cloud cluster (`ra5fptcofl`) decommissioned/replaced. | Migrate all 4 tables (`cas_index_estimates`, `index_weights`, `market_ticks`, `stock_orderbook_depth`) to new cluster `uwmxpy364g.ap-south-1.aws.clickhouse.cloud:8443`. | Migrated 365,455,242 rows across AWS backbone via `remoteSecure` with 100% exact count match. Updated all live streaming collectors (`clickhouse_streamer.py`, `stock_depth_collector.py`) and VM services. | ADOPTED |
| **DEC-010** | Pipeline Performance | Redis hash snapshot polling caused silent intermediate tick loss during volatility bursts; C++ hot path had heap JSON allocations and unpipelined synchronous calls. | P0 Option B: Decouple ClickHouse persistence into local append-only WAL (`data/tick_wal/`), pipeline Redis commands in C++, add baked commit hash verification and clean rebuild enforcement. | Zero tick loss on market bursts; Redis pipelining cuts latency from 5ms to <0.3ms; 90-day retention TTL controls cloud growth; baked Git hash guarantees remote binary alignment. | ADOPTED |
| **DEC-011** | Storage & Reliability | Write-Ahead Log (WAL) on AWS VM had no automatic file purging or storage ceiling, risking ENOSPC disk exhaustion on the limited 25 GB root EBS volume from millions of daily ticks. | Rotate WAL into bounded 25 MB segments (or 15 min), immediately delete completed WAL segments once ingested by `clickhouse_streamer.py`, enforce a 500 MB hard storage ceiling with FIFO pruning, statvfs disk guard (< 1 GB free space), and purge all WAL files in `eod_cleanup.sh`. | Keeps steady-state disk footprint under 50 MB (0.2% of disk); eliminates risk of disk exhaustion for Redis and OS; guarantees zero uncommitted data loss before deletion. | ADOPTED |
